# 省流阅读体验审查与改版

2026-10-20 · 目标：让第一次打开的人迅速抓住关键问题和高价值信息，能核对依据，也能带走总结。

本轮使用项目自编的虚构节目演示，实际操作本地阅读页，并检查生成、缓存和分享流程。以下结论来自界面审查和功能验证，没有进行真实用户访谈，也不代表所有来源平台已经实测。

## 2026-10-21：问题下直接给答案和信息

根据真实节目试读反馈，移除只列问题的重复目录。每张问题卡现在按“具体问题 → 省流答案 → 1–3 条最有价值的信息 → 未解处 → 背景与原文”排列。答案和要点默认可见，例子、机制和适用条件归到对应问题，独立章节只保留补充洞察。复制、保存和分享版使用相同内容；旧摘要没有要点时不虚构填充。

![新版问题卡：答案与高价值信息直接可见](assets/question-answer-preview.png)

下面保留 10 月 20 日的审查过程和当时截图；其中问题目录的展示方式已由本次调整替代。

## 1. 打开页面，先看到这期值得问什么

**原问题：** 人物介绍占据前排；原节目时长没有明确标签；问题字号和对比度偏低，答案却大面积加粗着色。手机双列卡片使每行文字过短。

**已改：** 首屏以“本期核心问题”为主标题，紧接完整、可点击的编号问题清单；结论、阅读时长和工具栏放在问题之后。清单直接突出部分回答和未解答的问题。人物与来源作为补充放到后面，保留黑金方向。

## 2. 快速扫读，内容各司其职

**原问题：** 问题被压成“从哪开始？”等泛化标题，脱离上下文就失去主体和具体矛盾；问答与洞察还会重复同一建议。

**已改：** 完整阅读后，先确定核心问题，再收集、排序、合并候选问题，最后核对回答范围。每个问题都必须独立可懂，并说明为什么重要、节目怎么回答、还缺什么及原文依据。区分节目直接提出的问题与从讨论中提炼的问题；回答状态描述节目覆盖程度，不表示事实已经核验。

示例保留 5 个具体问题、3 条补充洞察。“AI 流程要验证多少次，才能认定稳定？”标为部分回答：节目说明没有统一次数，却未提供具体的稳定判据。这个缺口直接出现在问题卡中，不在页尾重复。

生成规范、Markdown、网页与校验同步更新。新任务缺少核心问题或问题解释时不能完成；部分回答／未解答必须说明具体缺口，规范化后重复的问题会被拒绝。旧摘要兼容读取，不编造缺失状态。中英文篇幅目标仍为软约束，短节目不凑数。

![问题卡明确展示回答与缺口](assets/ux-review/question-gap.jpg)

吸顶目录只列出实际存在的内容，标记当前阅读位置；手机目录可横向滚动。正文不依赖外部字体、脚本或服务。

## 3. 查依据后，能回到刚才的位置

**原问题：** 点击引用进入长原文后难以返回；搜索无结果只留下空白区域。

**已改：** 原文默认折叠。点击本地引用会展开、清除旧过滤条件、定位并突出对应段落。返回入口固定在目录下方，返回时恢复刚才引用的键盘焦点。没有真实时间轴时继续使用段落编号。

支持回听定位的平台保留时间链接；其他来源提供原节目链接与本地原文定位，不制造不支持的跳转参数。

## 4. 带走总结，确保拿到的是正确版本

**已改：** 页面可复制摘要、下载 UTF-8 Markdown。内容来自同一份规范摘要，不夹带完整逐字稿。自动复制被浏览器拒绝时，展示已选中的文字供手动复制；未完成摘要不提供可用的复制/保存按钮。

同时修复交付路径中发现的问题：

- 分享脱敏误把 `https://` 当成本地路径，破坏外链和回听定位。
- 脱敏破坏隐藏 Markdown 中的链接，或把已转义内容恢复成活动 HTML。
- 总结尚未完成、语言已切换或文件已过期时，仍可导出旧结果。
- 复用同一输出目录或切换 RSS 集数时，残留上一来源信息或缓存。

分享和可移植导出现在先检查完成状态与文件一致性，脱敏后重新计算文件校验值；备份归档仍允许保存进行中的工作。
