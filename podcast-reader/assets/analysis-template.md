# 省流版编辑模板

这是 `evidence.json` 的内容组织指南，不是要求 Agent 另外手写一份长报告。默认 `summary` 模式由 finalizer 从结构化证据生成 `summary.md`、兼容的 `analysis.md` 和 `reader.html`。

目标：让读者在 3–5 分钟内看懂**这期真正要解决什么问题、为什么重要、回答到了哪里、还缺什么**。识别问题是主流程，不能写完结论后再套几个问句。短节目更短，不凑栏目。

完整长节目可参考中文正文约 **900–1,600 字**、英文约 **500–900 词**，包含可见总结的各个栏目。这是编辑目标，不是最低字数；短节目不为了达标扩写。阅读时长由生成器根据实际文字估算，不能固定写成“3–5 分钟”。

制作顺序：**读完整材料 → 确定核心问题 → 收集候选问题 → 按价值排序并合并 → 核对回答范围 → 补充洞察**。前 30 秒让读者看到每个关键问题及其下方的省流答案和最有价值的信息。不重复摆放只有问题的清单，不让读者跳到其他栏目或点击展开才能看懂答案。

## 核心问题、标题与一句话结论

- `digest.core_question`：一句独立可懂的具体问题，说清主体与矛盾。例如“普通人怎样判断 AI 真正帮上了工作，而不是只学会了一个工具？”
- 标题说清楚主题和最值得关注的问题，不使用来源不支持的夸张结论。
- 一句话直接给出节目最重要的答案；必要时保留决定答案的条件。
- 对应 `digest.headline`、`digest.takeaway` 和支持核心问题与结论的 `digest.evidence`。

## 关键问题 · 节目回答到哪里

先收集节目直接问过的问题，以及从具体讨论、例子和分歧中提炼的问题。按对理解或判断的影响、信息价值、真实未解处排序，再合并重复项。通常选择 3–6 个，短来源可更少。

每张新生成的问题卡必须包含：

- **问题 `question`**：脱离上下文仍可懂，保留主体、矛盾和关键条件。“普通人初学 AI，怎样选一个适合开始的小任务？”不能压缩成“从哪开始？”。不要以 6–16 字为目标删掉真正的问题。
- **为什么重要 `why_it_matters`**：来源支持的意义、判断或边界，不替受众编造动机与收益。
- **问题来源 `question_origin`**：节目明确问过为 `explicit`，允许忠实改写；从讨论中提炼为 `synthesized`，不能冒充主持人原话。
- **回答范围 `answer_status`**：`answered` 表示节目回答了该题范围，`partial` 表示只回答部分，`unanswered` 表示未给答案。这不是事实核验、正确性或置信度。
- **省流答案 `answer`**：紧接问题，先写实际回答，再保留关键条件。中文通常可控制在 30–60 字，但不能因此改变回答范围；没有答案就如实说明。
- **还缺什么 `gap`**：`partial` / `unanswered` 必填，指出确切未解处；`answered` 不填写。
- **出处 `evidence`**：同时覆盖问题来由、意义、答复与未解处，需要多个远处分段时分别引用。

例如，“一个 AI 流程要验证多少次，才能认定稳定？”对应 `partial`：节目解释任务差异、错误代价使统一次数不适用，却未给出具体场景的验证次数和稳定判据。不能为了凑一个状态就写成“完全未回答”。

对应 `digest.quick_takes`。重要未解问题也应在问题卡里呈现，不另在 `open_questions` 重复一次。所有新总结都要求上述字段，旧文件兼容不代表新内容可以省略。

每张新卡还应补充 **最有价值的信息 `key_points`**：1–3 条非空短句，每条最多 300 字。优先选择支持该答案的具体机制、例子、区别、方法或关键条件，并纳入同一张卡的 `evidence`。不要换句话重复答案，也不要为了填满三条而编造。如果来源没有额外细节则省略；旧文件没有该字段仍可读取。

卡片的呈现顺序为：**问题 → 省流答案 → 最有价值的信息 → 还缺什么 → 为什么重要、问题来源与出处**。答案、信息和实质缺口直接可见。问题来源和时间点提供复核入口，不应抢在答案前面。

## 高价值信息

通常选择 3–7 条，按重要程度排列。每条包含：

- **明确的观点标题**：说出发现，不只写主题名称。
- **解释**：比上方答案多提供一种机制、一个关键例子、一组具体步骤、一个适用例外或一处分歧，说明为什么会影响理解或判断。
- **必要补充**：可用少量短要点呈现步骤、条件、例子或边界。
- **出处**：覆盖该条的关键事实与归纳。

对应 `digest.insights`。已放进问题卡 `key_points` 的内容不在这里重复；独立洞察应补充新的理解。可选类型为判断启示、反直觉、数据与案例、方法、风险与边界、一般洞察。类型仅用于阅读提示，不要求凑齐。

保留真实分歧，区分嘉宾观点与综合归纳。关键限制紧跟对应结论，不只藏在页尾。如果删掉一条洞察后，读者没有少得到新理解，就合并或删掉它。

例如，问答已经说明“总耗时要算上复核”，洞察就展示节目中的具体计算或对照方法；再写一遍“要看整体效率”没有增加价值。

## 精选短引 / 行动建议（可选）

短引最多 3 条，必须逐字匹配所引原文。行动建议只在节目明确支持且有用时出现，附适用条件；文艺、故事、喜剧内容不强制转换成行动方案。

可选栏目各有用途：人物介绍帮助理解发言背景，短引保留值得记住的措辞，行动建议提供新的一步，未解问题保留真实的不确定性。只有重复内容时直接省略。

## 对谈双方 / 参与者（可选）

姓名、节目中的角色、一句来源可确认的介绍。单人节目可只有一人；身份未知时不编造履历。放在问题与洞察之后作为背景补充，对应 `digest.participants`。

## 来源与限制

保留来源、已知节目信息和具体限制。没有时间轴就使用文本片段编号，不能补造时间戳；缺少后半段就明确说仅总结已取得的部分。

写入 `episode`、`limitations` 以及各条 evidence 字段。最终报告不应包含本模板、占位符、制作过程或为了填版而生成的内容。
